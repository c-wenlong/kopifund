# Kopifund v3 audit, October 2026

A read-only review of the repo at `31c9974` (main, 18 Oct 2026). Nothing was
edited and `~/.kopifund` was not opened. Four reviews ran side by side (routes
and repo layout, types and schema, recurring payments, UI and notifications).
The findings marked "checked" were confirmed by reading the code again; the
recurring cadence findings were also reproduced by running the real detector on
made-up rows. `tests.test_recurring` (31) and `Recurring.test.tsx` (27) pass,
so none of the recurring cases below are covered by tests.

There is no `map.md` in the repo. [ROADMAP.md](../ROADMAP.md) holds the goals
and their milestone lists, so the roadmap at the end is written in its format.

Severity: **high** is wrong figures or lost data a user would act on;
**medium** is wrong in an edge case or will bite later; **low** is tidiness.

The layout is sound: parsers in `scripts/`, the sync and checks in `finance/`,
the stats in `analytics/`, the server in `serve.py`, the app in `web/`. Every
frontend API call has a backend handler. The problems are inside the Python
side.

## 6. Fixes and enhancements, in priority order

1. Ignore `.playwright-mcp/`, delete `scripts/concat_csv.py`, move `analytics/fixtures/` under `tests/fixtures/`, add `gen_runbook.py --check` to `make check` (R8, R9, R10).
2. Recurring schedule in `finance/recurring.py`: measure lateness from the last real payment, keep each missed slot listed as late, match payments to the nearest anchor day, never fill a later slot from this month (mark it "extra"), judge each series against its own account's last statement date; build Home's `recurring_off` from the same pick Recurring uses (P2, P3, P4, P5, P9).
3. Bucket colour and icon: `icon` and `colour` columns on `category_group` (in schema v5) with defaults in `analytics/categories.json`; `bucket_style` in `/api/spending` and `/api/categories`; `BucketIcon.tsx`; icon on Categories tabs, Where it went and chart legends; `colourFor` reads the stored colour (U1).
4. Shared types: `finance/types.py` TypedDicts with `Cents` and Literal enums, `scripts/gen_types.py` writing `web/src/types.gen.ts`, `tests/test_types.py` checking the file is current and each handler's keys match. api.ts re-exports the generated names so no import changes (T1, T8 TS half, T11, RT4).
5. Recurring detection in `recurring_detector.py`: cluster a payee's charges by amount so one payee can hold several series, fit period and anchor, rolling-median amount so a price step is a new price, add 14, 61 and 182-day cadences, allow 2 payments for yearly when the payee is marked recurring, add a paused state, apply the S$10 floor everywhere (P1, P6, P7, P8, P10, P11, P12).
6. Recurring series view and edit: `/recurring?series=<id>` opens a drawer on the Recurring page (no new tab) with cadence, usual amount, next date, status, the dot strip and the series' own rows; a `series_override` table (recurring yes or no, amount, cadence, day, ended on, ignore charge) read by the detector; "Not recurring" replaces "Edit rule"; every payee link and status chip on Recurring, Coming up and Needs your eye opens it (P13 to P16).
7. A `Sheet` component (centred dialog at 768px and up, bottom sheet below) with a `--scrim` token, and a `useUnsavedGuard` that `navigate` and `beforeunload` check (U2, U10).

9. Needs your eye in the sidebar: extend `overview.needs_your_eye` with the latest upload state, needs-rule count, `missing_fx` and stale accounts; an item above Your profile with a count badge (a dot on the rail and the phone menu button) opening the list; scam lines in the danger colour; Home's card keeps four lines plus "All N"; sidebar scrolls (U3, U11, U13).

## 7. Milestone roadmap

The milestones are goals G16 to G19 in [ROADMAP.md](../ROADMAP.md), one PR per
line. The owner's decisions on 18 Oct 2026 changed the list above in three ways:

- Bucket icon and colour columns (item 3) are part of schema v5 (item 13); the
  colour clash is fixed earlier, in the chart kit, by giving the palette enough
  colours that buckets never wrap.
- A new milestone gives every kind of thing an icon (bank marks wherever an
  account is named, transaction kinds, need, want and savings, cadences,
  statuses, upload steps, scam reasons), so the dashboard reads at a glance.
- Picking a bucket's icon and colour on Categories is its own PR after schema v5.

Confirmed: the Net worth inputs move into a dialog opened from a one-line
summary at the top; recurring series edits are stored in `kopifund.db` while
payee and category stay in the rules; "Needs your eye" is the alert list.

Every PR follows AGENTS.md: `make check`, then the make commands its area
needs (`make build` and a look at desktop and 375px for web; `make doctor` and
a load on a copy of the data folder for schema changes; `analyse --no-publish`
on a copy for the recurring work), and SPEC.md updated in the same PR when
behaviour changes.
